# Design Log #20260214183312

## Background
Joey wants to “embody” the Epsilon AI agent as a floating Halo Reach Forge Monitor orb using an existing FBX model (no face rig). The model includes a bright blue core/light element that can act as a “mouth” by brightening/dimming in sync with speech audio.

Target: short, repeatable videos with audio, generated by AI agents (script/TTS/orchestration), using a web-based renderer.

## Problem
Create a web-based pipeline that:
- Renders the monitor model convincingly (including textures).
- Makes the blue core read as “speaking” by modulating glow intensity from audio amplitude.
- Supports recording a clip (video + audio) to a downloadable file.
- Is automatable by an AI agent (e.g., via Playwright) without requiring manual 3D tooling.

## Questions and Answers
- Q: Should we do phoneme/viseme lip-sync?
  - A: No; the model has no face. Use audio amplitude (envelope) to drive emissive intensity of a “core” material/light.
- Q: Load FBX directly or convert to glTF?
  - A: Start with FBXLoader for fastest iteration using the provided asset. If FBX textures/materials become painful, add an optional conversion step later.
- Q: How to handle FBX texture paths?
  - A: Remap texture URLs at runtime by basename (FBX references Windows paths). Serve textures from Vite `public/` and use `LoadingManager.setURLModifier`.
- Q: How to record audio + canvas video?
  - A: Use `canvas.captureStream(fps)` + `MediaStreamDestination` for audio and combine tracks into a single `MediaStream` for `MediaRecorder`.

## Design
### Project structure
- `monitor-avatar/`: Vite (TypeScript) app.
- `monitor-avatar/public/assets/halo-reach-forge-monitor/`:
  - `source/NewMonitor11.fbx`
  - `textures/*.png`

### Rendering
- Three.js scene with:
  - Perspective camera, orbit-style controls optional (can be added later).
  - Hemisphere + directional light for base lighting.
  - Optional bloom pass for glow “pop” (keep toggleable for simplicity/perf).
  - Simple “floating” animation (bob + slow yaw) applied to model root group.

### “Mouth” glow
- Select one or more target materials.
- Drive a single scalar `talk_strength` in [0..1] derived from audio amplitude.
- Apply to:
  - `material.emissiveIntensity = idle + talk_strength * scale`
  - Optionally, a point light `power = base + talk_strength * scale`

### Audio analysis
Use WebAudio:
- `AudioContext` + `AnalyserNode` reading time-domain samples.
- Compute RMS amplitude per frame.
- Apply:
  - noise gate threshold
  - attack/release smoothing
  - compression/curve (e.g., `x^gamma`) so quiet syllables still show

### Recording
- Create combined stream:
  - Video: `canvas.captureStream(60)`
  - Audio: `MediaStreamDestination.stream`
- Record with `MediaRecorder` (`video/webm;codecs=vp9,opus` fallback to defaults).
- Download as `.webm`.

### Automation hook (agent-friendly)
Add URL query params (optional) to support headless orchestration:
- `?audio=/audio/line.mp3&autostart=1&record_ms=8000`
Agent can still click a “Start” button if autoplay is blocked.

## Examples
✅ When Epsilon speaks: core brightens quickly on syllable onset and slowly relaxes between phrases.
✅ When silent: core returns to a stable idle glow without flickering.
❌ No rapid strobing on background noise.
❌ No complete loss of textures due to Windows path references inside FBX.

## Trade-offs
- FBXLoader is convenient but can be less reliable than glTF in the web ecosystem; if we hit issues, converting to glTF is the next step.
- MediaRecorder `.webm` is the lowest-friction in-browser export; `.mp4` typically requires post-processing (ffmpeg) outside the browser.
- Audio amplitude is not true lip-sync; it’s a stylized “talk light” but matches the model constraints well.

## Update 2026-02-14
### Problem
The “talk spill” point lights currently feel like they are coming from the wrong place, especially as the monitor floats/rotates.

Root cause: the talk spill lights are world-anchored rather than being tied to the emissive parts of the model.

### Design delta
- Replace the current generic talk spill lights with talk spill sources that originate from the monitor’s emissive features:
  - front of the eye
  - back of the eye
  - LEDs
  - booster
- Attach the talk spill lights to the model root so they move/rotate with the monitor.
- Derive each light’s position from the actual meshes using `material_meshes_by_uuid` (bounding box center/extents in model-root space).
- Preserve the existing talk animation curve and overall intensity tuning; only redistribute where the spill appears to originate.

### Implementation approach
- Identify meshes for the relevant materials (InnerSphereMaterial / LEDS / BoosterMaterial, plus eye shell if needed).
- Compute a stable local-space AABB per material by transforming each mesh’s geometry bounds into the model-root coordinate space.
- Place point lights:
  - Eye front/back: use the eye core AABB and place two lights at the center, offset to the minZ/maxZ extents.
  - LEDs: use LEDS AABB center.
  - Booster: use BoosterMaterial AABB center.
- Gate light intensity based on whether the corresponding materials are selected for talk glow (so the UI selection still controls “what talks”).

### Implementation Results
- Replaced the world-anchored talk spill lights with 4 model-attached point lights (eye front/back, LEDs, booster) in `monitor-avatar/src/main.ts`.
- Positioned these lights using per-material bounds computed from the actual meshes (`material_meshes_by_uuid`) so the spill originates from the emissive features.
- Preserved the existing talk animation curve and redistributed the previous spill intensity across the new sources, gated by the selected talk materials.
- Tightened the LED spill light (positioned slightly outward and with a shorter range) and derived an LED emissive mask from the albedo texture so only the blue/cyan LED pixels glow (instead of the whole LED material).
- Ensured EyeMaterial / InnerEyeMaterial use emissive color + emissiveMap when selected so the eye glow affects the visible eye surfaces (not just the inner orb).
- Disabled env/IBL reflections for InnerSphereMaterial (eye core) while keeping it responsive to actual lights, to avoid “imaginary” side reflections.
- Switched the eye talk spill lights to directional spotlights aimed outward (front/back) so enabling eye glow doesn’t wash the inner sphere and create side highlights.
- Updated the recommended talk materials default to booster + eye shell + inner eye + LEDs.
